# VECTORCALC — desktop wrapper

Electron shell around the Flutter web build. It exists so the desktop app can be
built on Windows without Visual Studio (the native Flutter Windows target needs
the MSVC toolchain).

## How it works

1. `scripts/sync-web.js` copies `../build/web` into `./web`.
2. `main.js` starts an HTTP server bound to `127.0.0.1` on an ephemeral port and
   serves only files inside `./web`.
3. A `BrowserWindow` loads that URL. External navigation and popups are blocked;
   there is no preload script, no Node integration, and the renderer is
   sandboxed.

No outbound traffic. The loopback server exists purely because CanvasKit and the
service worker need an HTTP origin.

## Commands

```bash
npm install
npm run start           # sync + run unpackaged
npm run dist            # sync + NSIS installer and portable exe
npm run dist:portable   # sync + portable exe only
npm run dist:linux      # AppImage
```

Artifacts land in `desktop/dist`.

## Icons

`desktop/build-resources/icon.png` and `icon.ico` are generated by
`dart run tool/gen_icons.dart` from the project root. Replace them with your own
artwork if you rebrand, keeping the same file names.

## Notes

- The window is sized like a pocket calculator (470×830) but resizes down to
  380×620 and up to any size; the UI switches to a wide layout with a history
  rail above 1000 px.
- `devTools` is disabled in packaged builds.
- Linux/macOS builds work from this same folder on the respective host; only the
  Windows targets are configured by default.

## Troubleshooting: `winCodeSign` extraction fails

On a non-elevated Windows account, electron-builder unpacks its `winCodeSign`
helper archive with 7-Zip and fails on two macOS-only symlinks:

```
ERROR: Cannot create symbolic link : A required privilege is not held by the client
```

Fix it once by pre-extracting the archive without the `darwin` tree, so
electron-builder finds the cache and skips extraction:

```powershell
$cache = "$env:LOCALAPPDATA\electron-builder\Cache\winCodeSign"
$dest  = "$cache\winCodeSign-2.6.0"
$7z    = ".\node_modules\7zip-bin\win\x64\7za.exe"
& $7z x "$cache\115058399.7z" "-o$dest" '-x!darwin\*' -y
```

Or enable Windows Developer Mode, which grants the symlink privilege. The
`darwin` binaries are only used when signing macOS builds on a Mac, so omitting
them is safe for the Windows targets.
